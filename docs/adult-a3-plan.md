## 2. What is true today (read from the code on 2026-11-25; every line was grepped)

- `touch(save, kind, now)` is in `game/actions.ts` (the `TouchResult` interface at line 179, the function at 185). It returns `{ gained: 0, asleep: false }` when there is no living creature at home (`alive()`, line 36: the phase is `alive` and the creature has no `job`), `{ gained: 0, asleep: true }` for a creature that is asleep (night or nap), and `{ gained: 0, asleep: false }` for a poke, all before anything is paid. A pet or a tickle calls `noteCare`, then gives `tuning.affection.pet` (2) or `.tickle` (3) happiness, but at most `maxGainPerWindow` (15) per `windowMinutes` (60): `tuning.affection` in `data/tuning.ts` line 84, the window is `Creature.affection: { windowStart, gained }` (`state.ts` line 74, created in `sim.ts` line 102). The window resets when `now - windowStart >= 60 minutes` (lines 193 to 195), so after the clock is set back it does not reset until the clock passes the old end. `gained` is worked out before the clamp to 100, so a pet at 100 still uses the window and returns a positive `gained`.
- Petting in the picture (`ui/Stage.tsx`): a finger held on the creature for 450 ms starts petting, then one pet every 800 ms while held (lines 389 to 407). A plain tap is a poke: the creature startles and nothing is paid (`tap()`, line 295 on). Three taps inside 1,200 ms are a tickle (`touch(s, "tickle", t)`, the happy pose, four sparkles). A heart floats up only when `gained > 0`.
- The poses are `idle walk hop happy startle refuse wobble eat sleep rumble yawn`, the effects are `heart` and `sparkle` (`art/idle.ts` lines 17 to 30). No pose or effect is new in A3.1.
- `Creature.discipline` is 30 at hatching and nothing raises or lowers it; only combat reads it (the sulk chance, `data/combat.ts` line 32 and `game/combat/battle.ts` line 54: below 50, (50 - discipline) in a hundred, at most 30 percent, so a newborn's 30 sulks 20 percent of the time). The spec's "sulk never fires" (Spec 9) is wrong; what is true is that nothing raises discipline.
- A creature's optional fields (`job?`, `hp?`, `trained?`, `rung?`) are how a new field is added without a version bump: `Save.version` stays 3, and `migrateSave` (`state.ts`, line 216 on) coerces each. A creature is dropped with its save when it dies or retires, so a field on the creature starts again with the next egg.
- A creature can be `sleep: "night"` or `"nap"` (`state.ts` line 66; a nap ends by energy, `care.ts` line 51); `touch` treats both as asleep. A creature can be at home or in a field (`Creature.place`) and can be petted in both: the Stage refuses a pet only in the habitat and the arena (`Stage.tsx` line 397 on), and `touch` itself does not look at the place.
- Adult Mode is `settings.adultMode`, saved per profile; `isAdultMode(save)` is what the Stage already uses. Kid Mode stays as it is (CLAUDE.md section 12).
- Sync (`sync/sync.ts`): `noteSave(byPlayer)` marks a device changed only for a save made by a player action, never for a save that only carries the clock forward, and `planAfterPull` makes a device that is not marked adopt a newer server save. Petting goes through `game.act`, which is a player action.
- The Adult HUD (`ui/AdultHud.tsx`) is a strip (the creature's name and stage, the Book, Settings, the coin and material chips, the player) and a stat bar of five cells with a details card. Space is already short: decisions.md ("Space and size") measured the Adult room page at 360 x 640 as 83 px below the window at ratio 2 and 106 px at 320 x 568.
- Tests that read what `touch` returns, all on default (Kid Mode) saves, so they must pass unchanged because the Kid path is untouched and `levelUp` is a key that exists only on a level-up: `tests/actions.test.ts` lines 208 to 224, `tests/jobs.test.ts` line 263 (`toEqual({ gained: 0, asleep: false })`), `tests/special.test.ts` lines 102 to 163 (including a loop `while (touch(...).gained > 0)` up to the cap). Tests that use `touch(save, "pet")` as a care action and must also pass unchanged: `tests/helpers.ts` lines 62 and 84, `tests/growth.test.ts` lines 201 to 216, `tests/forecast.test.ts` line 594, `tests/playthrough.test.ts` line 107. Nothing in the existing suite is rewritten; the new rule is new tests. Only `ui/Stage.tsx` (lines 290 to 292) reads the result in `src/`.

## 3. Decisions for A3 (mine, each changeable)

1. **Kid Mode is unchanged:** the hard cap of 15 an hour, no Bond, no new word. The taper and Bond are Adult Mode only (`isAdultMode(save)`), like the Shop. `touch` has one extra branch, not two systems that disagree: the spec's "do not keep both" is read as "the adult path replaces the cap", and the Kid path is the old rule until the owner says otherwise. Reversible: one condition.
2. **Bond belongs to the creature,** not the household: a new egg starts at level 1. Legacy (what a retired life leaves) is Spec 8, A4.
3. **Unlocks the HUD names are only the ones that exist.** The spec says every level shows its unlock; naming a trick that is two slices away would promise it. In A3.1 only L2 (a happy bounce of its own now and then, the existing `happy` pose with a heart; **corrected while building: the plan said an idle `hop`, but `chooseNext` in `art/idle.ts` already picks `hop` for about a quarter of an ordinary creature's choices, so a hop would not have been new**) and L5 (a bigger heart and sparkle burst when petted, the existing effects) are real; each later slice adds its own (L3 and L7 tricks in A3.3, L4 the toy slot with the Shop's Toy Shelf, a later Shop slice, L10 the animation and the Book entry in A4). Levels with nothing to unlock still level up and say "Level 4". **Hat tolerance (the spec's L5 line) goes to A4,** with the arena: A2.4 left hats out of the arena and the hatch scenes on purpose (decisions.md, "Left out"), and "cosmetics stay on in-scene" means showing them there, which is combat art, not petting.
4. **XP is never tapered, only happiness is** (the spec: "always full Bond XP"). XP stops at the level 10 threshold so the number stays small.
5. **The streak** is the spec's "rhythm combo" read for the gesture the game really has. Only a held finger makes pets (one every 800 ms after 450 ms; a tap is a poke and three taps a tickle, and neither touches the chain). Pets one right after the other chain, and from the tenth pet in a chain (about 7 seconds of a held finger) each pet is worth 2 XP instead of 1. A gap of more than 2 seconds ends the chain. It changes XP only, never happiness.
6. **Poke stays free of reward and says so.** The spec's "wakes a dozing (not sleeping) creature" would be a nap, and I do not wake a nap with a poke: a nap ends by energy (`care.ts`), a poke waking it would add a rule to the care code and a way to cut a creature's rest short, and a napping creature is asleep for `touch` as it is today (no XP, no chain). "Starts a play invite" is A3.3. In A3.1 poke only gets its honest label in Adult Mode: "Poke: gets attention". Reversible: one more branch in `tap()`.
7. **The Bond display is placed after a measurement, not by a guess** (done, section 9: a chip in the bag row that opens a card, as (a) with (c)'s content on demand). Three candidates, in my order of preference: (a) one chip in the strip beside the bag chips, (b) a thin row under the stat bar, (c) a line in the stat details card. A quick mock at 320, 360 and 390 at pixel ratios 1, 2 and 3 (as the Home's H0 did) gives the real heights and widths before any code; the plan's figures are not summed.

## 4. A3.1 in detail

### The rules

- **Levels:** XP at which each level starts, `[tune]`: L2 300, L3 800, L4 1,500, L5 3,000, L6 4,500, L7 6,500, L8 9,000, L9 12,000, L10 15,000. Worked out for the spec's targets from 5 minutes of petting a day (300 s / 0.8 s = 375 pets, at most 9 + 366 x 2 = 741 XP): L2 in under a day, L5 in about 4 days and L10 in about 20 days of that, which real play (lifting the finger ends a chain, and not every day) stretches toward the spec's week and month. The later slices add XP sources, so these are retuned then.
- **XP per pet:** 1 while the chain is under 10, 2 from the tenth pet of a chain on; a tickle is 3, whatever the chain. Paid only for a pet or a tickle that `touch` pays today: a living creature at home (no `job`), awake (a night sleep and a nap both pay nothing), in Adult Mode. Where a pet can happen is the Stage's rule (the home and a field; the habitat and the arena refuse in the Stage, `touch` does not look at the place).
- **The taper of happiness** (replaces the 15 an hour cap for Adult Mode): per window of `windowMinutes`, a gain is the full amount while the window's gained points are under 15, half while under 30, a quarter after (`[tune]`): pets pay 2 eight times, then 1 fourteen times, then 0.5; tickles 3 five times, 1.5 ten times, then 0.75. The window restarts when `now - windowStart >= 60 minutes` **or when `now < windowStart`** (the clock went back). A pet is never worth 0, so the heart always floats; at 100 happiness a pet still uses the window and still pays XP, as it does today.
- **The Kid path is the old code, line for line** (the 15 an hour cap, the old window test, no `bond` key written); the branch is `isAdultMode(save)`, read on every call.
- **State:** `Creature.bond?: { xp: number; chain: number; at: number }`, optional; missing means level 1 with nothing saved. `xp` is a whole number from 0 to 15,000, **`chain` is stored saturating at 10** (a longer hold still pays 2 and stores 10), `at` is the game time of the last pet. About 40 characters.
- **The chain:** `gap = now - at`; the chain continues (chain + 1, capped at 10) when `0 <= gap <= 2,000` ms and otherwise restarts at 1, so a negative gap (the clock went back) restarts it and a gap of 0 (two touches in the same millisecond) continues it. Only a pet sets `at` and the chain; a poke and a tickle leave both alone.
- **Level-up:** `touch` returns `levelUp` only when a level was just reached (the key does not exist otherwise, so every existing `toEqual` on the result keeps passing); the Stage shows a sparkle burst and the HUD line, and one line goes to the dev log (at most nine per creature).

### Edge cases (a test for each; "(b)" is a browser check)

1. Kid Mode: `touch` gives the old numbers exactly (the 15 an hour total, no `bond` key written, a result of the old shape) and the screen is the same as `main` (b: the Kid comparison, 0 differences). The existing tests listed in section 2 pass unchanged.
2. Adult Mode, the taper: pets pay 2 eight times, 1 fourteen times, then 0.5; tickles 3 five times, 1.5 ten times, then 0.75; a new window after 60 minutes; the heart shows on every pet (b).
3. A pet or a tickle on a creature that is asleep (night or nap), dead, an egg or away on a job gives no XP and does not touch the chain.
4. XP: a pet adds 1 up to chain 9 and 2 from chain 10; a tickle adds 3; the total stops at 15,000; XP never goes down; the level is a function of XP alone and level 10 stays level 10.
5. The chain: two pets 2,000 ms apart chain, 2,001 ms apart do not; a gap of 0 chains; a clock that goes backwards (the device clock) restarts the chain at 1 and never makes a negative gap; a tickle or a poke between two pets changes nothing; a pet and a tickle at the same instant each do their own work.
6. The stored chain: a hold of 150 pets stores `chain` 10 and, after `migrateSave`, keeps its XP, its level and its chain (a longer hold never saves what the loader refuses).
7. Level-ups: crossing a threshold returns that level once, and the next pet returns no `levelUp`; no step can skip a level (the largest step is 3, the smallest gap between two levels is 300, L1 to L2).
8. A new egg, a death and a retire: the next creature has no `bond` key and is level 1.
9. Saves: a missing `bond` loads as level 1; a damaged one (a string, negative or fractional `xp`, `NaN`, `Infinity`, above the cap, a `chain` over 10 or fractional, a non-finite or negative `at`, extra keys, `constructor`, an array) is dropped whole, never throws and never keeps half of it; a Kid profile that has `bond` data keeps it untouched and shows nothing; `version` stays 3.
10. The window and the clock (Adult): set the clock back inside a window and the window restarts, so the taper starts again at full (a mutant removes the `now < windowStart` test and a test must fail).
11. Happiness already 100: a pet gives `gained` and uses the window as today, pays XP, and the heart shows; happiness stays 100.
12. The place: a creature in a field is paid like one at home (unit, `touch` is called directly); in the habitat and the arena a hold starts nothing (b, the Stage refuses it).
13. A mode change in the middle of a hold: Adult Mode switched off between two pets makes the second pet follow the Kid rule and leaves `bond` as it was; a Kid profile that carries `bond` data gets neither the L2 bounce nor the L5 burst (the idle and burst code read `isAdultMode`); a profile switch with a finger down does not carry the chain over.
14. The dev time speed: `at` is game time, so above about 2.5 times speed a held finger's 800 ms reads as more than 2,000 ms and the chain does not form; this is dev mode only and goes in known-issues (a test with `now` values shows the break).
15. Sync, the passive device: Bond changes only through `game.act` (a player action), so a pet marks the device as changed and is sent like any play; a device that only carried its clock forward is not marked changed and adopts the newer server save (`noteSave`, `planAfterPull`): a test in the style of `tests/game-save-hook.test.ts` shows a pet is a player save and a tick is not. An older build (`main`) that loads a save with `bond` keeps the field as it is (`migrateSave` passes a creature through without rebuilding it, so an unknown field survives a save) and earns nothing into it; a newer build then continues from the XP that is there. Nothing is lost, which is unlike the Playroom's item (known-issues G20).
16. The display (b): Adult Mode only; a name, a level, the progress to the next level and the next unlock that exists, readable at 320, 360 and 390 at pixel ratios 1, 2 and 3 with no clipped text and no sideways scroll (measured with a Range, not `scrollWidth`); the label for a screen reader reads "Bond level 3, 120 of 700 to level 4"; Kid Mode shows nothing new.
17. Poke in Adult Mode says "Poke: gets attention" in the stat or care help text; it still pays nothing and still startles (b); a poke on a napping creature does nothing, as today.
18. The unlocks: L2 makes the creature bounce for joy and show a heart now and then, on its own, when it is in a good mood (a test of the rolls with a pinned random source, and none below L2, in Kid Mode or in low spirits); L5 makes a pet's burst bigger; neither is shown to Kid Mode.
19. Growth is not skewed by accident: a 5 minute petting session in Adult Mode is measured against the old rule for the happiness cells it adds (a test over the real `countCareCells` of `game/growth.ts` and `fieldCells`); the number goes in decisions.md. If it changes which adult a creature becomes by a margin the owner has not seen, it is a question for the owner, not a quiet change.
20. The result's shape: every `touch` result that is not a level-up has exactly the old keys (the `toEqual` in `tests/jobs.test.ts` line 263 and `tests/actions.test.ts` line 224 are the net).
